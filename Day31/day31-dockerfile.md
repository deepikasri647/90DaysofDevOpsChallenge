## 📜 Task 1 & 2: Key Dockerfile Instructions Explained

* **`FROM`**: Specifies the base image upon which the custom image is built (e.g., `ubuntu`, `alpine`, `nginx`).
* **`WORKDIR`**: Sets the active working directory inside the container for subsequent instructions.
* **`COPY`**: Copies local files/directories from the host machine into the container filesystem.
* **`RUN`**: Executes bash commands during the **build phase** to install packages or dependencies (creates a new layer).
* **`EXPOSE`**: Documents the network port on which the container application listens at runtime.
* **`CMD`**: Specifies the default command to execute when a container starts up.

## ⚡ Task 3: CMD vs. ENTRYPOINT

| Feature | `CMD` | `ENTRYPOINT` |
|---|---|---|
| **Purpose** | Sets default parameters or commands that can be overridden easily. | Sets an explicit executable that always runs when the container starts. |
| **Override Behavior** | `docker run image custom_cmd` completely replaces the `CMD`. | Arguments passed in `docker run image arg1` are appended to `ENTRYPOINT`. |

### When to use which?
* Use **`ENTRYPOINT`** when designing executable utility images (e.g., a custom wrapper script or CLI binary where the primary binary shouldn't change).
* Use **`CMD`** for default runtime arguments or when users need flexibility to override startup commands.
* Combine both: Use `ENTRYPOINT` for the binary executable and `CMD` for default arguments.

## 🚀 Task 5 & 6: Build Optimization & `.dockerignore`

### 1. Purpose of `.dockerignore`
Similar to `.gitignore`, a `.dockerignore` prevents unnecessary files (`.git`, `node_modules`, `.env`, temporary logs) from being copied into the Docker **Build Context**. This reduces build times and keeps final images secure.

### 2. Why Layer Order Matters for Build Speed
Docker caches each layer generated by instructions like `RUN` and `COPY`. 
* If a layer changes, **all subsequent layers below it lose their cache** and must rebuild.
* **Best Practice:** Place infrequently changing instructions (like installing dependencies via `RUN apt update`) near the top, and place frequently changing instructions (like `COPY . .` for application code) near the bottom!
